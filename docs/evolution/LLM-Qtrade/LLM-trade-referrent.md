
交由LLM进行初步的意图识别和任务规划，详细说明细节，包含prompt内容。

我们来深入剖析 OpenClaw 中 LLM 进行**意图识别**和**任务规划**的细节。这部分是整个智能体正确执行任务的关键，主要依赖于精心设计的**系统提示词（System Prompt）** 和**用户提示词（User Prompt）** 的组合，以及 LLM 被要求输出的结构化规划结果。

---

## 1. 整体输入结构：系统提示词 + 用户提示词

OpenClaw 在调用 LLM 之前，会将以下信息拼接成一个完整的提示词发送给 LLM：

- **系统提示词**：固定部分，定义 LLM 的角色、能力边界、可用的 MCP 工具列表、输出格式要求、思维链指引等。
- **用户提示词**：动态部分，包含用户的原始输入、当前会话上下文、历史消息等。

### 系统提示词的核心内容示例

```
你是一个专业的加密货币投资分析助手，集成在 OpenClaw Agent 框架中。
你有能力调用一系列 MCP 工具来获取实时金融数据。
请严格遵守以下规则：

1. 仔细理解用户的问题，识别其深层意图。
2. 如果问题需要外部数据，将任务拆解为多个步骤，并规划调用工具的序列。
3. 调用工具时，必须按照以下 JSON 格式输出：
   {
     "action": "call_tool",
     "tool_name": "具体的工具名",
     "arguments": { "参数1": "值1", ... },
     "reasoning": "解释为什么调用这个工具，以及它如何服务于整体任务"
   }
4. 如果不需要更多工具调用（数据已足够），则输出最终答案，格式为：
   {
     "action": "final_answer",
     "content": "你的分析结论和建议"
   }
5. 每一步只能调用一个工具。你将在下一轮收到工具返回的结果，然后决定下一步。

可用的 MCP 工具列表（名称 + 参数 + 返回描述）：
- crypto_price(symbol: str) -> 返回当前价格、24小时涨跌幅、成交量
- fetch_ohlcv(symbol: str, timeframe: str, limit: int) -> 返回K线数据（时间、开高低收）
- calculate_rsi(symbol: str, period: int) -> 返回RSI值
- calculate_macd(symbol: str, fast: int, slow: int, signal: int) -> 返回MACD线、信号线、柱状图值
- get_btc_dominance() -> 返回比特币市值占比
- ...（其他工具）

现在，请基于用户的输入，开始你的分析和规划。
```

> 注：实际系统中系统提示词会更长，包含角色设定、输出格式约束、错误处理、安全规则、上下文限制等。

## 2. 意图识别：LLM 如何“理解”用户到底要什么

用户输入可能模糊、隐含条件或复合多个需求。LLM 的意图识别本质上是一个**从自然语言到结构化目标的翻译过程**。

### 示例输入与 LLM 内部推理

**用户输入**：`“分析下 BTC 最近涨得猛不猛，能不能追？”`

**LLM 的隐含推理路径**（虽然我们不直接看到中间过程，但系统提示词会鼓励它先思考再输出）：
1. **目标**：判断 BTC 是否处于强势上涨，并给出追高建议。
2. **所需信息**：
   - 近期价格变化（涨幅、K 线形态）
   - 目前价格位置（是否脱离底部）
   - 市场情绪（RSI 是否超买，成交量是否配合）
   - 可能的阻力位或支撑位（需要历史高点数据）
3. **任务类型**：技术分析 + 主观风险评估。
4. **可用的 MCP 工具匹配**：
   - `crypto_price` -> 获得当前价格和涨幅（“涨得猛不猛”的基础）
   - `fetch_ohlcv` -> 拿最近几天的K线，看阳线实体长度和连续性
   - `calculate_rsi` -> 判断是否超买（>70 不建议追）
   - `calculate_macd` -> 看动量是否持续

**输出规划（第一步）**：
```json
{
  "action": "call_tool",
  "tool_name": "crypto_price",
  "arguments": { "symbol": "BTC" },
  "reasoning": "首先获取 BTC 的实时价格和 24h 涨跌幅，以确认当前基本涨幅情况。"
}
```

经过几轮工具调用后，LLM 会收集所有数据，然后输出最终分析。

### 意图识别的难点与处理

- **隐含比较**：“哪个币最抗跌？” → LLM 需要规划调用多个币种的跌幅数据，然后排序。
- **未来预测**：“BTC 下周能到 10 万吗？” → LLM 应意识到无法预测未来，但可以通过历史波动率、持仓量、资金费率等间接指标给出概率评估（如果有对应工具）。
- **复合意图**：“ETH 突破前高了没？如果突破了，帮我算一下从突破点到现在涨了多少。” → LLM 需要先调用价格历史获取前高值，比较当前价，条件性执行后续计算。

系统提示词可以强化“如果...那么...”的逻辑处理能力。

## 3. 任务规划：将意图拆解为可执行的工具调用序列

任务规划并不是一次性生成所有步骤，而是**生成第一步 -> 执行 -> 观察结果 -> 生成下一步**的循环。这是 ReAct (Reason + Act) 模式的典型体现。

### 多步规划示例

**用户**：`“比较 ETH 和 SOL 过去 7 天的 RSI 走势，谁更超卖？给出抄底建议。”`

**LLM 推理**：
- 需要两个币种的 RSI 时间序列。
- 工具 `calculate_rsi` 只返回当前值，要“过去 7 天”需要先获取 7 天的 OHLCV 数据，然后自行计算 RSI 序列？或者存在一个 `get_rsi_history` 工具？根据已知工具列表，只能用 `fetch_ohlcv` 拿原始 K 线，然后要求 LLM 计算？但 LLM 不擅长精确计算，最好由 MCP 工具提供 RSI 历史值。
- 假设有一个工具 `get_rsi_history(symbol, period, days_back)`，但它不在列表中 → 说明该 MCP 服务不够完善。实际中 OpenClaw 可能要求 LLM 在规划时忽略不存在的工具，或报错并建议替代方案。

**更合理的规划**（如果只有当前 RSI 工具）：
- 用户要求“过去 7 天的 RSI 走势”无法满足，只能提供当前 RSI 值。LLM 应主动说明限制，并建议使用当前的超卖程度作为参考。

**系统提示词中关于规划的限制**：
- 每个步骤只能调用一个工具，因为工具结果可能改变下一步的规划（例如，`crypto_price` 返回“该币种不存在”时，规划应终止或询问用户）。
- 工具之间可能有依赖关系：先获取 symbol 列表，再逐个调用价格。
- LLM 必须维护一个“已完成步骤”的列表，避免重复调用。

## 4. 结构化输出：让 OpenClaw 可解析的规划

OpenClaw 要求 LLM 的输出必须是严格的 JSON，以便程序自动解析并执行动作。

### 工具调用的输出格式（详细版）

```json
{
  "action": "call_tool",
  "tool_name": "calculate_rsi",
  "arguments": {
    "symbol": "BTC",
    "period": 14
  },
  "reasoning": "RSI 是判断超买超卖的关键指标。14 周期为标准设置，如果 RSI > 70 表示可能追高风险大，RSI < 30 表示超卖。",
  "expectation": "工具应返回一个 0-100 之间的数值，我将根据该值判断 BTC 目前是否过热。",
  "next_planned_tool": "fetch_ohlcv"  // 可选的链式提示
}
```

### 最终答案的输出格式

```json
{
  "action": "final_answer",
  "content": "根据最新数据，BTC 现价 $65400，24h 涨幅 3.2%。RSI(14) 为 68.5，接近超买线。MACD 柱状图开始缩短，上涨动能减弱。近 3 天 K 线出现较长上影线，存在抛压。\n\n**综合判断**：目前追高风险较大，建议等待回调至 MA20 支撑位（约 $63200）再考虑入场。",
  "suggested_follow_up": "如需自动设置价格提醒，可以说“在 BTC 跌到 63200 时通知我”。"
}
```

## 5. 增强规划能力的 Prompt 技巧

为了提升 LLM 的规划质量，系统提示词中常包含以下技术：

### a) 思维链（Chain-of-Thought）引导

要求 LLM 在输出 JSON 之前，先用自然语言写出“思考过程”（但最终只输出 JSON 或同时输出两者）。例如：

```
在输出 JSON 之前，请先用 <thinking> 标签写下你的推理过程，包括意图分析、信息需求、工具匹配等。
```

### b) 错误恢复规划

```
如果某个工具调用返回错误（如 symbol 不存在），你应该输出一个 final_answer 说明问题，而不是继续调用其他工具。或者询问用户提供正确的 symbol。
```

### c) 并行调用提示

如果系统支持并发工具调用，可以允许 LLM 输出一个数组：

```json
{
  "action": "call_tools_parallel",
  "calls": [
    { "tool_name": "crypto_price", "arguments": { "symbol": "ETH" } },
    { "tool_name": "crypto_price", "arguments": { "symbol": "SOL" } }
  ],
  "reasoning": "同时获取两个币种的价格以比较涨幅。"
}
```

### d) 短期记忆与上下文压缩

在长对话中，LLM 的上下文窗口有限。系统提示词应指导 LLM 在规划时引用历史关键结果（例如：“之前已经获取过 BTC 价格，不需要重新调用”）。OpenClaw 一般会在发送给 LLM 的消息中包含前面几轮的工具调用和结果，但需要 LLM 主动识别重复。

## 6. 一个完整的端到端规划运行示例

**用户输入**：`“ETH 最近有没有出现金叉？我想买入。”`

**发送给 LLM 的完整提示词**（简化版）：
```
系统：... （如前面所述）

历史消息：无

用户：ETH 最近有没有出现金叉？我想买入。
```

**LLM 输出（第一轮）**：
```json
{
  "action": "call_tool",
  "tool_name": "calculate_macd",
  "arguments": { "symbol": "ETH", "fast": 12, "slow": 26, "signal": 9 },
  "reasoning": "金叉是指 MACD 线从下方上穿信号线。需要获取当前 MACD 值和信号线值，并对比前几天的值来判断是否刚刚形成金叉。但该工具只返回当前值，无法判断趋势。因此我首先获取当前 MACD 状态。"
}
```
（实际上，更好的做法是先调用 `fetch_ohlcv` 取得多日数据，但为了简化，假设 MCP 提供了 `get_macd_history` 工具。本例中按实际设计来）

**OpenClaw 执行**：调用 `calculate_macd` 返回 `{ "macd": 15.2, "signal": 12.8, "histogram": 2.4 }`。

**第二轮发送给 LLM**：添加上一轮的工具调用和结果。LLM 看到当前 MACD 线（15.2）高于信号线（12.8），说明处于金叉之后的状态，但无法知道是否“最近”形成。于是：

**LLM 第二轮输出**：
```json
{
  "action": "call_tool",
  "tool_name": "fetch_ohlcv",
  "arguments": { "symbol": "ETH", "timeframe": "1d", "limit": 10 },
  "reasoning": "为了判断金叉何时形成，需要过去 10 天的 K 线数据，我可以手动计算 MACD 的变化（如果系统允许 LLM 计算），或者期望 MCP 提供更直接的指标。这里先取得原始数据。"
}
```

**OpenClaw 执行**：获取 10 条日 K 线。

**第三轮**：将 K 线数据发给 LLM（数据量可能很大，LLM 可能无法处理 10 天的完整 OHLCV，许多 Agent 会使用 MCP 工具直接计算历史 MACD 而非传入所有数据）。为避免过载，MCP 应提供 `get_macd_history`。假如没有，LLM 可以承认无法精确判断，给出近似结论。

**最终 LLM 输出**：
```json
{
  "action": "final_answer",
  "content": "根据当前 MACD 值（15.2）和信号线（12.8），MACD 线仍位于信号线上方，但无法确定金叉发生的时间点（需要历史数据）。从价格行为看，ETH 过去 3 天连续上涨，成交量温和放大。若金叉是在 3 日前形成，则上涨趋势可能持续。建议结合 RSI 指标（当前 RSI 65）判断：未超买，小仓位买入可行，止损设于前低。"
}
```

## 总结

OpenClaw 中 LLM 的意图识别和任务规划依赖于：
1. **详细的系统提示词**，定义了角色、工具列表、输出格式、思维链指引。
2. **ReAct 循环**：LLM 每次只决定下一步动作（调用一个工具或输出最终答案），执行后观察结果再决定下一步。
3. **结构化输出（JSON）**，使 OpenClaw 能解析并安全调用 MCP 工具。
4. **意图识别**：通过语义解析将用户的模糊需求转化为具体的信息需求（如“金叉” → MACD 历史数据比较）。
5. **规划能力**：LLM 需考虑工具依赖、错误处理、上下文重复调用避免等。

这种设计使得 LLM 可以像一个“操作员”一样，一步步获取必要的信息，最终生成有数据支撑的投资决策。
